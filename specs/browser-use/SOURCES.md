## Trusted Current Code

These are **Hermes implementation details** checked September 24, 2026, not a portable configuration schema for other harnesses. ## Weak Claims To Avoid

- No ten- or twenty-agent authenticated live test, cloud profile persistence pilot, Kernel MCP deployment, standalone agent-browser installation, or Camofox rollout occurred in these six reports. Their vendor recommendations conflict and are not current default policy. The September 24 three-worker read-only pass does not establish larger-scale authenticated isolation or concurrent writes.
- A named Hermes session on the current CDP override may get a separate tab **in the same Chrome**. An MCP server name or connection is not per-agent browser ownership; tools with optional active-session state need explicit IDs. A copied cookie/localStorage file is a credential-bearing snapshot, not a fresh independent login. Cloud profile read replicas do not isolate site-side changes to one account.
- The reported Hermes backend precedence differs between code readings and docs; CLI auto-attachment to a local debug port, Browser Use profile binding/save timing, Kernel OAuth/client behavior, Camofox headed login and per-site concurrent-login tolerance remain to be verified in any future pilot. The reports' '2–3 per site' pacing is a conservative proposed starting point, not a tested safe rate. Vendor CAPTCHA-solving and stealth claims do not authorize bypassing a site's challenge or terms.
- A connected MCP server or visible tool schema in Hermes does not prove a successful Hermes navigation call, and a Jev `done` decision does not independently prove its goal.
- A separate headless Jev Chromium does not inherit Chrome login or control macOS apps. A browser's headed mode alone does not make it authenticated or make its automation permitted by a site.
- A successful `/json/version` request does not establish the right Chrome profile, site account, tab, login persistence, agent action approval, or remote gateway behavior.
- A shared localhost CDP endpoint has no per-agent access separation; being bound to loopback does not authenticate local clients or justify exposing it through an unauthenticated tunnel.
- The Chrome command and V2 OpenCode config in the owner handoff were **examples when written**. The Chrome/CDP launch was later tested on this Mac, but OpenCode's new authenticated route was not configured in this Hermes session; check its installed version and its own native schema separately.
- The September 19 primer referenced by the handoff was not provided in this task. The retained portable connector registry is an awareness inventory, not evidence those connectors are currently live.
- A reported profile-copy issue does not show every Google login fails; a hosted provider's stated persistent-profile feature does not prove the user's site login survived a restart. An estimated Jev cost is not a verified bill.
- Relocating records within this shared repository does not make them private. Neither the new root source bundle nor the earlier nested Jev bundle may store browser profile data, cookies, or credentials.
