# ChatGPT website: new conversations, mode and model

Load `~/agents/skills/chatgpt-browser/SKILL.md`. Sending is an account write. Inspect the live site before using dated selectors, and obtain authorization for the prompt, model and any billable setting. Do not infer execution model or cost from a generic label.

1. At `https://chatgpt.com/` or the exact project home, select `button[data-tpp-toggle-value='chatgpt']` for Chat or `button[data-tpp-toggle-value='work']` for Work; require the selected `aria-checked=true`. These are **composer modes**, not separate project types. A new project may inherit the global mode. Project-only memory can make Work unavailable.
2. Open `main button.__composer-pill` and inspect the current model and effort. In one observed Work menu, explicit GPT-6 choices appeared in `[role=menuitemradio]`, with an effort slider `[data-model-reasoning-effort-slider]`. Choose only an authorized *live* option and verify the readback (for example `GPT-6 Luna / Medium` in one test). Chat's `Latest`, `6 / Pro`, and `Medium` are UI labels, not independent proof of the backend model. Model catalogs and user cost preferences belong to the active runtime's policy, not this portable website skill; never silently substitute a deprecated or costlier model.
3. If explicitly requested, `button[aria-label='Add files and more']` opens a tool menu; `Web search` selection should yield a visible `Web search` pill and `Search the web` placeholder. Do not mistake that for evidence a search ran. Work's `Files`, `Plugins`, and `Open desktop app` are affordances, not proof of local filesystem permissions.
4. Compose in the visible editor: `#prompt-textarea[contenteditable=true]` in older observations; on 2026-10-09 project pages it was a `.ProseMirror[contenteditable=true]` named `New chat in <project>` with no id (see `research-chats.md`). `main textarea` can be a **hidden fallback** (`display:none`) and filling it can send an empty turn. Place the caret after any search pill; use the adapter's actual keyboard/text insertion; read visible `innerText` back and confirm the whole prompt, mode, model and effort **before** clicking `button[aria-label='Send prompt']` once. On a timeout, check for a new turn before retrying.
5. Require new `/c/<id>` or project `/g/<project>/c/<id>`, echoed user turn, finished assistant turn, and any requested citation/tool evidence. Citation presence alone is not answer-quality evidence. Reopen project home and require the card after reload when project persistence matters. Preserve initial mode if this was a transient test and the user did not request a lasting mode change.

Existing conversation search: `button[aria-label='Search']` opens `[role='dialog'] #global-search-modal-input`; results use `[data-testid='global-search-results-scroller']`. If controlled-field fill does not persist, use the adapter's real keyboard insertion and verify the input's value. Search results are not a complete history inventory.
