# ChatGPT website: export conversations and reports

Load `~/agents/skills/chatgpt-browser/SKILL.md`. Read-only extraction must not create a new chat or change a project. Revalidate all selectors against the hydrated page. Treat report artifacts and generated files separately from surrounding assistant turns. Preserve existing chat titles during exports: do not rename chats unless the user explicitly requests renaming. When a title lacks a batch code, match the first prompt and report topic to the exact chat ID and record the mapping in the export index. If the user requests title repair, use the specified code and topic, verify each title after an independent project reload, and update the index; keep export status in the index rather than adding a transient status to the title.

## Destination and conversation folder

- For a **whole-conversation export**, create one folder under `~/Downloads` by default, or under the directory the user supplied. Use a filesystem-safe conversation title plus a short thread identifier for a stable, distinct folder name; use `conversation` when the title is unavailable. Keep it private and avoid overwriting an existing export: use a distinct suffix if needed. A single-message or single-artifact request may produce one file instead.
- Save each message as its **own Markdown file** in display order: `00-user.md`, `01-chatgpt.md`, `02-user.md`, and so on. Pad to at least two digits, increasing the width for very long threads. Keep consecutive assistant messages as separate files. Use the message's native Copy when verified; otherwise label that file's rendered conversion in the index.
- Export **every accessible attachment or artifact associated with the conversation** as a separate file in the same folder, including deep-research reports and generated Markdown documents. Prefix it with its parent message's number and role, then a type and a short filesystem-safe name: for example, `01-chatgpt-deep-research-search-quality.md` or `01-chatgpt-document-handoff.md`. Preserve a non-Markdown artifact's real extension and bytes. If no descriptive name is available, use `artifact-01`; add a suffix for collisions. Never substitute the surrounding message text for an artifact.
- Include a `README.md` that lists messages and artifacts in reading order with relative links, source conversation URL, extraction method and coverage limits. Record message IDs and hashes in a private manifest if useful for verification. If any identified artifact cannot be exported, list it as missing in the index and report the conversation export as incomplete; do not silently omit it or claim a complete export. Keep temporary clipboard/download files in restricted staging, then verify every final file in the chosen folder before reporting its path.

## Identify and inventory a thread

- Open an **observed** `/c/<thread>` or `/g/<project>/c/<thread>` link. Sidebar `a[href^='/c/']` is recent/pinned only, not full account history. Project cards `main a[href*='/c/']` can be capped. `button[aria-label='Search']` opens `[role='dialog'] #global-search-modal-input`; results scroll in `[data-testid='global-search-results-scroller']`. A search mention of research or a Sources button does **not** prove a report exists. Do not infer absence from a bounded search.
- After hydration, collect `[data-message-author-role]` with `data-message-id` and role in display order. Some user turns use `[class*='whitespace-pre-wrap']` instead of `.markdown`. Require nonempty selected bodies; IDs or assistant HTML can arrive before user text. Preserve consecutive assistant turns and observed order. Never invent missing turns.
- If `[data-message-author-role]` is absent, inspect the live page for `[data-chatgpt-search-unit-key]` and `[data-chatgpt-search-message-ids]`. In one September 2026 thread these held ordered `fallback-turn-N:...:user|assistant` units and message IDs; assistant ID attributes repeated the same ID twice. Deduplicate within each unit, not across the conversation. `h4.sr-only` labels (`You said:` / `ChatGPT said:`) provided a second role check. These are observed fallbacks, not stable selectors.
- Expand any user-turn `Show more` before capturing text. A page-text snapshot taken while it was collapsed contained a literal ellipsis in the middle of the message, even though other turns were present. Capture again after expansion and check that `Show less` replaced the control. A later page-text capture may contain only a subset of turns despite the DOM still reporting all ordered units, so a single whole-page text dump is not completeness proof.
- Find the **ancestor containing the messages** whose computed `overflowY` is `auto` or `scroll` and `scrollHeight > clientHeight`. Measure `scrollTop`, `scrollHeight - clientHeight`, `clientHeight`. Start at measured top; traverse with overlapping steps no larger than 70% of viewport, collect IDs/roles at each stop; reach measured bottom; reverse to top and compare the unique ID sets and order. `window.scrollY`, Home/End, or a count at one viewport does not prove completeness. Reopen at least one thread after hydration and compare ordered IDs/roles and per-turn content signatures.
- During that walk, inventory **artifact hosts as well as message units** at each stop. In a September 2026 thread, four completed Deep Research reports appeared as `iframe[title='Deep research']` only after the relevant part of the conversation was physically scrolled into view. Their frames were outside the message-unit elements and did not appear in a whole-page text capture. A zero iframe count at one scroll position therefore does not establish that the thread has no reports. Map each report host to its surrounding turn before exporting, then revisit each host and verify the report count against the thread's research turns. Do not equate a brief `Deep Research has started` message with the report body.

## Single response and ordinary conversation

- Find the **specific message's ancestor section** and its own `[data-testid='copy-turn-action-button']` with `aria-label='Copy response'` or `Copy message`. The Copy control can be outside `[data-message-author-role]` but inside its `section`. A global last Copy button is unsafe. Scroll target into view; if the toolbar is inert until hover, hover and check the hit target before a physical click. Reobserve after a timeout.
- Before each Copy, save the host text clipboard privately and place a fresh random marker. Click the exact target's control, read host clipboard as bytes, and require nonempty bytes different from the marker and attributable to that target. A successful click or stale clipboard is not success. Write bytes directly to a new access-restricted private file in a restricted staging directory, without transcribing through the model. Restore and verify the original clipboard afterward. Browser-side clipboard reads may be denied although the host clipboard changed. Serialize clipboard-dependent workers.
- For a full regular chat, copy **each discovered turn** to a separate ordered payload; include role, ID and hash in a private manifest. Publish the verified per-turn files and index in the conversation folder above. Revisit measured endpoints and reopen the thread to compare ordered IDs/roles and content. If a Copy fails, use target-local rendered HTML (`.markdown` or the observed user bubble) converted to Markdown and label **that turn** a rendered conversion. Verify headings, code, lists, tables, links, and tokens where possible. An owner-provided last assistant response passed target-bound native Copy and DOM structural comparison; **a full per-turn Copy transcript has not been independently audited end to end**. Do not claim source-Markdown, hidden branches, file binaries, or whole-account completeness from this method.

## Distinguish generated document from research artifact

- A generated `.md` **document card** is separate from the assistant reply. Bind the card by its exact observed filename `button[aria-label='<filename>.md']`, then its adjacent card-local `button[aria-label='Download file']`. A tested fallback opens that card's in-chat Library side viewer and uses its header `button[aria-label='Download']`. The standalone Library at `/library?entry_point=sidebar` can locate the exact filename with `input[placeholder='Search library']`; in its full-screen viewer use `More actions` > `Download` > `Markdown document .md`. The in-chat viewer's menu and full-screen viewer's menu differ. A surrounding `Copy response` yielded only the short reply, not the large document. Full-screen viewer `Copy` gave text but was not byte-identical to the downloaded Markdown.
- A **deep-research report** is an embedded artifact. Observed hosts include an out-of-process `connector-openai-deep-research.web-sandbox.oaiusercontent.com` iframe and, later, `mcp-app-*.web-sandbox.oaiusercontent.com` inside `iframe[title='Deep research']`; the latter also used a nested `iframe#root`. Inspect the live frame tree rather than hard-coding one host. The frame URL's initialization ID can change when the report remounts after scrolling, so reacquire it when returning to a report. The report card's `Expand` button opened a full-height side viewer in one tested thread; use that view to inspect a truncated inline preview, and close it after extraction. Target the report's own `Export` > `Export to Markdown`; do not substitute the enclosing response's Copy. A tested backup is a *physical* frame-local `Export` > `Copy contents` with a fresh clipboard marker and direct byte transfer. In one Chrome extension session, the physical Copy changed the **host** clipboard while the browser clipboard API still returned the marker; checking only the browser clipboard would have falsely marked the copy as failed. A synthetic DOM click on `Copy contents` also did not pass the marker check. Save the report separately with its parent turn's filename prefix. If neither native route works, label DOM-to-Markdown a rendered snapshot, not the site's report export.
- For downloads, use an authorized adapter's private download staging area, inventory before clicking, require exactly one **new completed nonempty** file and no unfinished `.crdownload`, then rename privately and restrict the saved file's access. If a browser-wide download override is used, restore its prior/default behavior in `finally`. A download event without a completed file or a click return is not final evidence; some adapters save a completed file directly in staging even when their separate save operation reports an error. One tested ChatGPT report's Markdown download and native Copy were byte-identical; do not assume future exports always match.

## Coverage labels

State exactly which of: one response, per-turn rendered transcript, generated `.md` document, report artifact, expanded research panels, attachments, citation targets, or account archive was captured. Collapsed controls, images, citations and file binaries were not covered by ordinary rendered extraction. ChatGPT Settings > Data controls > Export is an asynchronous account-wide alternative, **not tested as a per-thread Markdown export**; do not conflate it with this procedure. Do not print transcript bytes, private names/IDs or report text in tool output. Close only task-owned tabs and restore shared clipboard/download settings even on failure.

For threads that contain brief `Deep Research has started` replies, do not infer that the corresponding reports are in the rendered conversation. Inventory report artifacts separately and label a turn-text export accordingly. Plain `innerText` or page-text captures also flatten tables and omit link destinations; label them rendered text, not source Markdown or a link-complete archive.

## Batch report exports: October 2026 observations

- A research brief can produce a full standard Chat report at Pro effort, with the entire report in the assistant response and no separate artifact. Inspect the live artifact inventory and response headings. When the response itself contains the complete requested report, its target-bound native Copy is a valid Markdown export; label it a full-response report copy. Do not look for a Deep Research Export menu merely because the prompt says “deep research.” Prefer a separate report/file artifact whenever one exists.
- Native Copy can return before the clipboard updates. After placing a fresh marker and clicking, allow a short bounded wait for changed nonempty content; check the existing result before clicking again. An immediate marker read is not proof of failure.
- The Projects directory can expose `Toggle project` controls and named `Chats in <project>` lists. Expanding them is an in-page action. Bind each `Open chat` to its exact observed row; opening that chat is a navigation and must observe the five-second pacing rule.
- For a multi-provider report batch, use one user-specified Downloads parent with `chatgpt/` and `claude/` children and `<code>-<short-title>.md` names. Keep reruns collision-safe, verify each saved file, and record the extraction method and any missing artifacts. This does not replace the per-turn layout for whole-conversation exports.

## Report and file exports through the signed-in API: 2026-10-09 observations

Tested by a Claude in Chrome agent on four chats (two Deep research, two standard Chat at Extra High and Pro). Read-only; nothing was sent.

- **Status check without opening each chat.** In a page on `chatgpt.com`, `GET /api/auth/session` returns an access token; `GET /backend-api/conversation/<id>` with `Authorization: Bearer <token>` returns the message tree. A finished Chat run has an assistant `text` message with `end_turn: true` and a `reasoning_recap` such as `Worked for 65m 32s`. Each message's `metadata.resolved_model_slug` shows the model that really ran. **This JSON can lag a running chat by many minutes**: one Chat run's JSON stayed frozen while its live page kept a Stop button. For a running chat, also check the live page.
- **Deep research reports are not in the message text.** The chat only holds a short "Deep Research has started" reply. The report lives in the `api_tool.call_tool` tool message under `metadata.chatgpt_sdk.widget_state` (a JSON string). Inside it: `report_message.content.parts[0]` is the Markdown, `report_message.metadata.citations[]` has `start_ix`, `end_ix` and `metadata.url/title`, plus `status`, `research_started_at`, `research_stopped_at` and per-step plan statuses. Turn markers like `【34†L1260-L1263】` into links by replacing each `start_ix..end_ix` span from the end backwards. Label the file a rebuilt export, not the site's own Markdown export.
- **The report card's download and expand buttons did not respond** to extension clicks (they are in a cross-origin frame). The API route above avoided them.
- **Deep research facts worth checking every run:** `report_message.metadata.resolved_model_slug` was `deep-research-mini` at both Extra High and Pro; plan steps were left `pending` when the report finished (the report was cut short); the page header said `0 citations · 0 searches` although the report had citations.
- **Generated `.md` files from Chat runs.** The final reply links `sandbox:/workspace/...`. `GET /backend-api/conversation/<id>/interpreter/download?message_id=<final message id>&sandbox_path=<url-encoded path>` returns `download_url`; fetching that gave the full file (410 KB) byte-exact.
- **Moving bytes to disk.** A blob link with `download` attribute worked once, then Chrome silently blocked later ones (its multiple-downloads guard). A local HTTP receiver was refused by the harness safety check; do not use one. What worked: arm a one-time `click` listener that calls `navigator.clipboard.writeText(text)`, make one physical click on empty page space, then read with **`LANG=en_US.UTF-8 pbpaste`**. Without the UTF-8 locale, `pbpaste` dropped non-ASCII characters. Back up and restore the user's clipboard, and compare the saved character count with the source length.
- **Recovering a stalled Chat run's file.** One Extra High run stopped mid-turn (last message `end_turn: false`, no final reply, Stop button shown for about 45 minutes, then idle). Its code messages referenced `/mnt/data/<name>.md`. Calling the same `interpreter/download` endpoint with the **last message's id** and that `/mnt/data/...` path returned the finished file (169 KB, all sections). Before rerunning a stalled chat, search its code messages for written file paths and try this first. Label the saved file a recovered draft, since the model never presented it.

### More API export pitfalls (second benchmark, 2026-10-09 evening)

- **Extra High chats can hold two end-turn assistant messages.** The second
  repeats only the tail of the first, starting at a later heading. The live
  page shows one answer. Export the first complete one; "the last
  `end_turn` message" can be a fragment (6,566 of 19,567 characters once).
- **6 Pro text carries citation markers** (`genui` plus JSON, wrapped in
  private-use characters U+E200 to U+E201). `metadata.content_references[]`
  gives `start_idx`, `end_idx` and a ready Markdown `alt` link for each;
  replace spans from the end backwards. Skip the last `sources_footnote`
  entry (no `alt`). Extra High text already has plain Markdown links.
- **Deep research plan-step statuses can be stale.** A completed report
  can still show 1 or 2 of 5 steps done. Do not read them as "stopped
  early"; judge the report.
- **Batch clipboard transfer works:** join many exports into one payload
  with start and end delimiters, one physical click, then split on disk.
  Give the last file an end delimiter too.
- The browser tool may block JavaScript output that contains URL query
  strings; return counts and lengths instead.
