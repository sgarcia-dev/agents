# Signed-in browser routes

Before a private task, record three distinct facts: **browser identity** (which profile owns the site login), **location/visibility** (local visible, local headless, or hosted), and **controller/connection** (native tool, MCP/CDP, extension, CLI, or desktop). The same CDP Chrome may accept several controllers without creating separate logins. A tab or named controller session is not a new account. Read `~/agents/specs/browser-use/spec.md` and current `STATE.md` for the tested local identities and limits.

## Local choices

- **Dedicated visible Chrome plus loopback CDP:** The owner signs into a distinct persistent profile; a native CDP-capable browser tool, Playwright MCP `--cdp-endpoint`, DevTools MCP, or a bounded script may attach to that **same** running browser. Verify the endpoint really binds loopback, the exact profile, and an account-only control. Raw CDP offers broad profile access and no per-client authentication. Never start two Chrome processes on one data directory; a handshake does not prove the site login. See `~/agents/capabilities/browser-native.md`, `~/agents/capabilities/mcp/playwright.md`, and `~/agents/capabilities/mcp/chrome-devtools.md`.
- **Chrome extension on a UI-added profile:** Playwright MCP can attach to a specifically named Chrome identity. This differs from CDP on a separate top-level data directory. Its browser-side connection approval and the agent harness's own tool approval are separate gates. A profile token is a credential: store it privately, never in the shared repo or a tool trace. See the Playwright guide.
- **Persistent browser per agent:** An isolated local profile may be manually signed into once and reused after a complete browser restart. Merely saving cookies or seeing a login before restart is insufficient; verify each site's account-only control afterward. See `~/agents/capabilities/browser-cli.md` and `parallel.md`.
- **Jev:** Stock MCP starts signed out. Its library can receive a caller-owned page from a signed-in browser, but this is a separately implemented and supervised path, not inherited authentication in the stock tool. Its autonomous long-thread scroll failed the documented pilot; see the Jev guide.

Ask the owner to perform passwords, MFA, CAPTCHA, native remote-debugging permission, and other human-only gates in the visible browser. Reobserve after handoff. Never copy personal cookies or send secrets through chat/model-visible logs. Check origin, exact tab, current site login, and requested account-only state before acting; verify target state afterward and close only owned tabs. If the Mac/gateway is asleep or the dedicated Chrome is down, none of the local attachments is automatically available. Do not describe historical login tests as current session health.
