# Parallel browser work

Treat **job/worker, controller session or browser ID, tab/page, and login profile** as separate ownership keys. A different tab does not isolate cookies, permissions, process memory, or writes to the same online account. Do not trust a shared controller's implicit current tab: pin an explicit page/browser ID on every call or use separate servers/profiles. One process must exclusively own a persistent profile directory. Keep account-changing actions, host clipboard, browser-wide download settings, native dialogs, and controllers without pinned tab ownership serialized.

Use the smallest pilot that proves the proposed isolation: two independent public pages with distinct final URLs, then a profile/cookie-separation check, then a complete cleanup to zero. Expand only after RAM, billing, site concurrency and owner handoff are measured. A dated five-browser public-page pilot covered standalone agent-browser, separate Playwright MCP server/profile pairs, Browser Use Cloud named sessions, and Camofox identities. It did **not** prove five signed-in agents or safe same-account writes. Those temporary Hermes test profiles were subsequently removed. The signed-in three-Hermes-worker pilot was short, read-only, and used deterministic CDP scripts for two workers; it did not prove free-form multi-agent browsing.

Use `~/agents/capabilities/browser-cli.md` for standalone sessions, `~/agents/capabilities/mcp/playwright.md` for per-agent servers, and `~/agents/capabilities/browser-hosted.md` for hosted/service choices. Keep the default user profile out of pilots. On timeout, check whether the old job left an owned tab or metered session before retrying. Close exact owned targets, disconnect clients without killing shared Chrome, stop owned cloud browsers, then independently list remaining sessions and processes. Report unresolved ownership instead of closing another user's page. Do not call an N-agent test passed when only N-1 results or cleanups are verified.
