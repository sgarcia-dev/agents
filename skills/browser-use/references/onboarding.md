# Onboard a browser route into one harness

This reference applies to `/sync-tool-adapter` in the **target harness's own session**. The shared skill and connector guides are source material, not native configuration. Audit the harness's effective tool/connector inventory and permissions first. Do not inspect or edit another harness's native configuration in this run.

1. Inventory the task's required browser identity and controls: public-only versus signed-in; local/hosted; DOM, clipboard, download, file input, desktop; serial versus parallel; user takeover and restart requirements. Read the relevant guide linked from `~/agents/capabilities/connectors.md`.
2. Classify the bridge: built-in/native (may need no installation), maintained default-off MCP (configure **off** when supported by the harness; turn on only with a recorded choice), or awareness-only optional CLI/API/desktop route (do not install or enable by registry inclusion). A non-MCP route still belongs in the audit and its adapter mapping. Missing enable/permission decisions remain questions, not implied approval.
3. For a selected route, verify version and command/schema in the **active harness**; pin tested dependencies, preserve unrelated settings, and keep keys/tokens/profile bytes in a private store. Never paste a profile token or raw CDP connection URL into the shared workspace or chat. Treat a credential as access to all exposed signed-in tabs. Do not silently choose the owner's everyday Chrome.
4. Reload the active harness if necessary, test a harmless public navigation **through its actual tool surface**, then, only if approved, test the intended signed-in identity via an account-only control. Verify tab/session cleanup, browser-process restart and site persistence separately when the requested use needs them. A package installed, MCP discovery, or listener health is not a page test.
5. Record in that harness's adapter its actual tool names, effective enablement and approvals, private handoff mechanism (not secret value), tested identity and highest verification tier; leave unsupported routes explicit. Reconcile the portable guide only for a lesson that applies across harnesses. A harness-specific syntax fix belongs in its own adapter or wrapper.

A sync run can make shared instructions discoverable and configure approved bridges; it cannot transfer a login, wake an offline Mac, bypass a site restriction, or guarantee equal runtime capabilities across harnesses.
