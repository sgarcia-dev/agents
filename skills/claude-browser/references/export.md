# Claude.ai website: export turns, documents and research panels

Load `~/agents/skills/claude-browser/SKILL.md`. Do not send messages or modify projects for a read-only export. Reinspect selectors after hydration, and keep output private.

## Destination and conversation folder

- For a **whole-conversation export**, create one folder under `~/Downloads` by default, or under the directory the user supplied. Use a filesystem-safe conversation title plus a short chat identifier for a stable, distinct folder name; use `conversation` when the title is unavailable. Keep it private and avoid overwriting an existing export: use a distinct suffix if needed. A single-message or single-artifact request may produce one file instead.
- Save each transcript row as its **own Markdown file** in reading order: `00-user.md`, `01-claude.md`, `02-claude.md`, and so on. Pad to at least two digits, increasing the width for very long threads. Preserve adjacent assistant rows as separate files. Use the row's native Copy when verified; otherwise label that file's rendered conversion in the index.
- Export **every accessible attachment or artifact associated with the conversation** as a separate file in the same folder, including embedded documents, Markdown cards and research outputs. Prefix it with its parent row's number and role, then a type and short filesystem-safe name: for example, `01-claude-document-design-notes.md` or `02-claude-research-sources.md`. Preserve a non-Markdown artifact's real extension and bytes. If no descriptive name is available, use `artifact-01`; add a suffix for collisions. Never substitute the surrounding message text for an artifact.
- Include a `README.md` that lists rows and artifacts in reading order with relative links, source conversation URL, extraction method and coverage limits. Keep row indices and hashes in a private manifest if useful for verification. If any identified artifact cannot be exported, list it as missing in the index and report the conversation export as incomplete; do not silently omit it or claim a complete export. Keep temporary clipboard/download files in restricted staging, then verify every final file in the chosen folder before reporting its path.

## Inventory and native per-turn Copy

1. Open an observed exact `/chat/<id>` or `/cowork/...` route. The transcript has `[data-testid='transcript-row'][data-index][data-perf-row]` (`human` or `assistant`); relevant subtrees are `[data-testid='user-message']` and `[data-testid='assistant-message']`. Wait for stable row indices, roles, content lengths, and tool-pill counts, not just nonempty text. Adjacent assistant rows are valid.
2. Find the nested scroll pane with computed `overflow-y:auto` and nonzero measured `scrollHeight-clientHeight`. Start at measured top, advance in overlapping small increments, dispatch a real scroll event when the adapter sets `scrollTop` programmatically, wait for virtualization, and collect rows by `data-index`. Reach measured bottom, then revisit top. A long thread once displayed only indices 23–27 of 28 at bottom; an event-driven incremental walk recovered contiguous 0–27. Require contiguous 0..N-1 before calling the visible transcript complete.
3. Bind Copy to each **specific** row. For a human row, its row-local `button[aria-label^='Show message actions']` exposes `button[data-testid='user-message-copy'][aria-label='Copy']`; the opener may need a DOM click if hidden pointer handling intercepts it. For assistant rows, hover then physically click `button[data-testid='action-bar-copy'][aria-label='Copy']`. Never use a global Copy button or accept the first nonempty clipboard before hydration settles.
4. Save the host clipboard privately, place a new random marker before **each** click, require changed nonempty bytes, and write those bytes directly to separate access-restricted private files with role/index metadata. Publish the verified per-row files and index in the conversation folder above. Reopen/reload and recopy each row with new markers, comparing bytes/hashes; restore/read back the prior clipboard. An observed three-row Cowork task (human, assistant, assistant) passed independent byte-identical per-turn recopy. Attachment thumbnails, Cowork Outputs and hidden tool details were omitted in that test. If Copy remains unchanged, convert the hydrated **row-local subtree** to Markdown and label it a rendered conversion, not native Copy.

The tested panel was `[role='region']` with `button[aria-haspopup='menu']`. In one sample the two were byte-identical. The enclosing assistant turn's Copy does not include this document.
- **Explicit Markdown card:** Bind the exact `[data-testid='transcript-row'][data-perf-row='assistant'] [data-sheet-kind='markdown']`, not a nearby HTML card. Prefer its exact-name `Download` button. In the opened panel, `[role='group']` contains `button[aria-label='More options']` > `Download as MD`, a second tested file route. Its panel `Copy` lacked only the final LF byte compared with the two byte-identical downloads in one test. The generic document's `[role='region']` / `Download as Markdown` controls **do not apply** to this card.
- Stage downloads privately: inventory a restricted directory, click the exact target, require exactly one new completed nonempty file (not `.crdownload`), rename to a private `.md`, restrict access to the saved file, and check disk readback. If the adapter changes browser-wide download behavior, restore it in `finally`. A download event or an adapter's separate save error does not settle whether the completed file was written directly into staging. Restore clipboard and close only owned tabs even on error.
