# Claude.ai website: create Chat and Cowork sessions

Load `~/agents/skills/claude-browser/SKILL.md`. Sending a prompt creates account state and may incur usage. Obtain authorization and verify the live mode, model, effort and editor before sending once.

1. Start at the observed `/new` page or exact project home. Select Chat or Cowork `[role=radio]` and require `aria-checked=true`. The sidebar `Search` is **account-content search**, not the composer Web search tool. Project-specific new sessions must be verified in project Recents after independent reopen.
2. Open `button[aria-label^='Model']` and inspect live choices and Effort menu. Selecting a model can **inherit or reset effort unexpectedly**: one Sonnet 5 selection inherited Extra until Medium was explicitly chosen. One tested Haiku 4.5 menu offered only Extended, so do not assume a lower-effort choice exists. Read back the exact model/effort label (for example `Model: Sonnet 5 Medium`) immediately before send. A transient model label during loading is not an execution-model or billing audit. Model catalogs and cost limits are runtime/user policy; stop if the authorized pair is unavailable rather than silently choosing a costlier option.
3. For Chat Web search, `button[aria-label='Add files, connectors, and more']` exposed a checked **Web search** item and separate Research item in one test. The Cowork plus menu lacked an explicit Web search toggle even though a tested task later reported web-search tools. Do not grant files, connectors, local devices, screenshot or plugin permissions just to test search; menu visibility is not permission or actual tool use.
4. Fill the **visible** `[data-testid='chat-input'][contenteditable]` (`aria-label='Write your prompt to Claude'`), then read back the complete prompt, mode and model label. Long-paste handling and editor serialization are described below; an empty editor can coexist with a pasted-text card. Click the enabled `button[aria-label='Send message']` for Chat or `button[aria-label='Start task']` for Cowork exactly once. If an action times out, inspect the resulting route/transcript before retrying to avoid duplicate sends.
5. For a request to wait for completion, require the new `/chat/<id>` or `/cowork/...` pathname, echoed user turn, finished assistant result, and, if requested, actual search/tool or citation evidence. Chat showed `Claude finished the response` and `Searched the web`; Cowork showed Progress/Outputs/Context and a completed cited result. Citation presence is not a source-quality check and UI selection is not a measured cost. A public-answer pilot did not prove file-system access or broader reliability.

A project Chat and Cowork task each survived independent project reopen in the observed test. Preserve unrelated sessions, project membership and initial mode unless the user directed a lasting change.


## Research launch without waiting (observed 6 October 2026)

- In each new project Chat composer, open **Add files, connectors, and more** and inspect **Research** and **Web search** separately. In the observed batch, Web search stayed checked but Research reset to unchecked on every return to the project home. Enable Research each time and require the checked **Research mode** control before sending. Do not infer Research from the prompt wording.
- A long multiline paste may become a **Pasted text** card, leaving the editor empty. Use that card's **Edit Pasted text** control to reopen its contents before verification. In the tested editor, each source line became a direct paragraph child; joining those children's text with one newline reproduced the exact source, including blank lines and indentation. `innerText` added extra paragraph spacing, while `textContent` alone removed line separators. Inspect the actual structure before using this comparison on a different editor. Reopening the card enabled normal inline submission in this test.
- Send exactly once and record the new chat identity. An introductory assistant reply, **Loading research capabilities...**, or **Activating research mode...** is only an intermediate state. Require a research card showing **Searching for sources...** or another active research stage before reporting the research as started. **Claude finished the response** can describe the introductory reply while the research card is still running; it is not proof that the report is complete. For start-only work, stop waiting once the active card is visible and do not require the final report or citations.
- If the user supplies a clarification fallback, send it only if Claude actually asks clarifying questions. Do not add an unsolicited follow-up to make research start.
- The header **<title>, rename chat** button opens a **Name** text field. Fill the requested title and press Enter, then require the exact title on the header and independently reopened project Recents. Renaming during activation worked in this test. Preserve pre-existing project chats and create one new chat per requested brief.
